# 모바일 도록 서비스 구성안

작성: 2026-11-13

## 결론

- **사이트는 하나, 전시는 데이터로 추가한다.** 지금처럼 작가마다 코드를 복사하면 5명만 넘어가도 관리가 불가능하다.
- 주소: `도메인/작가영문명`. 작가 1명이 여러 전시를 열면 `도메인/작가영문명/2026-부귀영화`.
- 계정 단위는 **'작가'가 아니라 '전시'**로 잡는다. 작가 계정 아래에 전시가 쌓여 그대로 포트폴리오가 된다.
- skill 은 '코드 복사 + 배포'에서 **'데이터 만들기 + 등록'**으로 바꾼다. 배포는 처음 한 번만 하고, 이후 전시를 추가할 때는 다시 배포할 필요가 없다.

## 1. 단계별 구성

| 단계 | 시점 | 구성 | 전시 추가 방법 |
|---|---|---|---|
| 1단계: 통합 | 지금 ~ 첫 유료 고객 5명 | 도록 2개를 앱 하나로 합침. 전시 내용은 저장소의 `exhibitions/<주소>/content.json` + 이미지 | skill 이 폴더를 만들고 커밋하면 자동 배포 |
| 2단계: 관리 화면 | 고객 10명 전후, 수정 요청이 잦아질 때 | 내용·이미지를 DB와 파일 저장소로 이동. 가족이 직접 고치는 편집 화면 | 관리 화면 또는 skill 이 API 로 등록 |
| 3단계: 결제·셀프 신청 | 수요가 확인된 뒤 | 신청서(브로셔·사진 업로드), 결제, 기간 관리 | 신청 → skill 이 초안 생성 → 사람이 확인 후 공개 |

처음부터 3단계를 만들지 않는다. 고객 요구를 듣고 고도화하는 계획과도 맞는다.

## 2. 1단계 상세 (지금 할 것)

### 폴더 구조
```
platform/
  app/[artist]/[[...exhibition]]/page.tsx   ← 도록 화면 (지금 코드 그대로)
  app/[artist]/admin/                         ← 전시별 관리자
  app/page.tsx                                ← 서비스 소개 + 작가 목록(공개 동의한 분만)
  exhibitions/
    kimsunrye/2026-buguiyounghwa/
      content.json      ← 지금 lib/content.ts 내용
      works/*.webp      ← 워터마크 들어간 1600px
      works/thumb/*.webp
      og.jpg, artist.webp
    jung-inyoung/2026-heenoaerak/ ...
```

### 지금 코드에서 바뀌는 것
| 항목 | 현재 | 통합 후 |
|---|---|---|
| 문구·작품 | `lib/content.ts` (코드) | `content.json` (데이터) |
| 색 | `globals.css` 직접 수정 | `content.json` 의 theme 값 → CSS 변수 |
| 기능 차이 | 폴더 복사 후 코드 수정 | `features` 값 (물주기, 동료작가, 연락처 종류) |
| 방명록 | 사이트별 저장 공간 | 저장 공간 하나, 경로를 전시별로 분리 |
| 관리자 비밀번호 | 사이트별 환경변수 | 전시별 비밀번호 (해시로 저장) |
| 배포 | 전시마다 Vercel 프로젝트 | 프로젝트 1개 |

### 주소 방식
| 방식 | 예 | 판단 |
|---|---|---|
| **경로 (권장)** | `도메인/kimsunrye` | 설정이 간단하다. QR·카톡에 충분하다 |
| 하위 도메인 | `kimsunrye.도메인` | 보기에는 좋지만 와일드카드 도메인 설정이 필요하다. 2단계에서 원하면 추가 |

### 전시 종료 후
- 기본은 **'보관' 상태**: 작품과 작가 소개는 계속 보이고, 방명록 쓰기만 닫힌다.
- 작가에게는 이게 가장 큰 가치(평생 포트폴리오)이므로 유료 상품의 핵심이 된다.

## 3. skill 개편

| 항목 | 현재 | 개편 후 |
|---|---|---|
| 작업 범위 | 코드 복사, 수정, Vercel 프로젝트 생성, 배포 | `content.json` + 이미지 생성, 커밋 (1단계) / API 등록 (2단계) |
| 걸리는 시간 | 30분 | 15분 안팎 (작품 모서리 지정 시간이 대부분) |
| 쓸 수 있는 곳 | sunrye 저장소 세션 | 플랫폼 저장소 세션 (1단계), 어디서나 (2단계, API 사용 시) |
| 구성 | 단일 skill | 하나로 유지하되 단계를 명확히: ① 브로셔 분석·질문 ② 초안 생성·미리보기 ③ 사진·피드백 반영 ④ 공개·QR |

추가할 것:
- `content.json` 형식 정의(schema)와 검사 스크립트: 빠진 값, 글자 수, 이미지 크기를 자동 확인
- 미리보기 주소: 공개 전 작가 가족에게 먼저 보여 줄 비공개 주소 (`?preview=토큰`)
- 체크리스트 출력: 고객에게 보낼 확인 요청 문구(초안 작가의 말, 제목 불일치 등)를 자동으로 만들기

## 4. 유료화 전에 확인할 것 (직설)

| 항목 | 내용 | 상태 |
|---|---|---|
| **Vercel 요금제** | 지금 쓰는 Hobby(무료) 요금제는 상업적 이용이 금지된 것으로 알고 있다. 유료 서비스면 Pro(월 약 20달러)가 필요할 가능성이 높다 | 확인 필요 (Vercel 약관) |
| **겸직** | 한국특허정보원 재직 중(2026년 말 퇴직 예정) 유료 서비스를 하면 기관의 겸직 규정에 걸릴 수 있다. 정식 유료화는 퇴직 후로 미루거나 사전에 확인하는 것이 안전하다 | 확인 필요 (기관 규정) |
| 사업자등록 | 돈을 받으면 필요하다. 온라인 결제를 붙이면 통신판매업 신고도 필요할 수 있다 | 확인 필요 |
| 개인정보 | 방명록이 이름을 받는다. 개인정보 처리방침과 보관 기간이 필요하다 | 1단계에서 함께 작성 |
| 작품 저작권·초상권 | 작품 사진과 작가 사진 게시 동의를 서면(문자 캡처라도)으로 받는다 | 신청 절차에 넣기 |
| 1인 운영 한계 | 지금 방식은 창균님 + Claude 세션이 필수다. 고객이 늘면 수정 요청 대응이 병목이 된다 | 2단계 편집 화면이 해법 |
